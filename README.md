# Rust Telegram Monitor

Telegram-бот для Rust+, построенный по сценарию Rustradar: в `.env` хранится только токен Telegram-бота, а каждый пользователь подключает свой Steam/Rust+ аккаунт самостоятельно.

## Как работает подключение

1. Пользователь устанавливает `rustPlusPlus-Credential-Application` и входит через Steam.
2. Приложение выдаёт строку вида:

   ```text
   /credentials add gcm_android_id:... gcm_security_token:... steam_id:... issued_date:... expire_date:...
   ```

3. Пользователь отправляет **всю строку** боту в личном чате.
4. Бот извлекает FCM credentials, удаляет сообщение с секретом, сохраняет данные зашифрованными и запускает listener.
5. Пользователь открывает Rust и нажимает **Pair with Server**.
6. Pairing notification приходит через FCM. Бот автоматически извлекает `server`, `port`, `playerId` и `playerToken`, создаёт отдельное Rust+ подключение этого пользователя и начинает мониторинг.

Для друзей повторяется тот же процесс. У каждого Telegram ID собственный FCM listener, Rust+ аккаунт, chat mirror, active mode, избранная РТ и настройки уведомлений.

## `.env`

```dotenv
BOT_TOKEN=токен_от_BotFather
POLL_INTERVAL_MS=15000
TIMEZONE=Europe/Moscow
DATA_DIR=./data
```

Steam-пароль, Steam cookie, player token и IP сервера в `.env` больше не нужны.

## Что есть в боте

- нижняя Telegram-клавиатура с кнопками **Обновить**, **Сервер**, **Тимейты**, **Чат**, **Время**, **Настройки** и **РТ**;
- Telegram Mini App с live-картой сервера, реальными РТ из `getMap`, магазинами, событиями и расположением тимейтов; маркеры обновляются отдельно, а изображение карты запрашивается редко, чтобы не упираться в лимиты Rust+;
- сервер показывает название, онлайн/max online, очередь, карту, размер карты, seed и wipe, если Rust+ отдаёт их через `getInfo`; IP и порт остаются рядом как запасной вариант;
- карточка **Тимейты** показывает ники, жив/умер, онлайн/вышел и последнее зафиксированное время выхода;
- двусторонний режим **Чат**: обычный текст из Telegram уходит в Rust+ team chat, а сообщения тимейтов приходят обратно в Telegram;
- игровое время в формате `HH:MM` — десятичное значение Rust+ вроде `18.0787` превращается в `18:04`;
- опрос Rust+ по умолчанию идёт каждые 5 секунд, а map markers проверяются отдельно каждые 2 секунды;
- **Настройки**: общее включение уведомлений, отдельные переключатели смерти игрока, тимейтов, рейда, хранилища, рассвета, заката и РТ;
- префикс Rust-команд на выбор: `/`, `.`, `!`, `@`, `$`. В team chat работают `<префикс>help`, `time`, `team`, `markers`, `server`, `rt`, `loot`, а также команды HP стен;
- **РТ** на русском с категориями: РТ, заправки, склады и магазины; у каждого объекта показывается квадрат/координаты marker, если их прислал сервер;
- каталог включает основные монументы Rust, нефтевышки, карго, военные объекты, заправки, склады, аванпост, лагерь бандитов, ранчо, рыбацкую деревню и магазины; таймеры можно корректировать по фактическим наблюдениям;
- появление избранной РТ и окончание её таймера дублируются в Rust team chat;
- Smart Alarm для уведомлений о возможном рейде, Storage Monitor для изменений хранилища, online/offline и alive/dead статусы;
- при срабатывании Smart Alarm тревога рейда повторяется в Telegram каждые 30 секунд до нажатия кнопки **«Проснулся — отключить тревогу»**; `/raidtest` запускает тестовую тревогу;
- новые vending/shop markers отправляют квадрат, название магазина и до 8 позиций лута; появление cargo, нефтевышки, Deep Sea Oil Rig, вертолёта и карьера отправляется отдельными уведомлениями;
- FCM death-события разбираются отдельно: бот понимает `grid`, `position`, `x/z` и другие варианты позиции, поэтому квадрат смерти берётся даже при формате события из FCM; если API не передал позицию, бот прямо укажет это;
- команды `дерево хп`, `метал хп`, `камень хп`, `мвк хп` считают ориентировочное время гниения от текущего HP; базовые значения можно скорректировать через `RUST_DECAY_MULTIPLIER`;
- `/forget` для полного удаления своей Rust+ привязки.

## Запуск

```bash
cd rust-telegram-monitor
npm install
cp .env.example .env
# впиши BOT_TOKEN
npm start
```

### Mini App

Мини-приложение слушает `WEB_APP_PORT` (по умолчанию `8787`). Чтобы Telegram показал кнопку
**Открыть live-карту**, укажи в `.env` публичный HTTPS-адрес:

```dotenv
WEB_APP_PORT=8787
WEB_APP_URL=https://your-domain.example/mini-app
```

Один и тот же адрес должен проксироваться на порт `8787` этого процесса. Telegram передаёт
`initData`, бот проверяет его подпись своим `BOT_TOKEN`, поэтому чужой пользователь не сможет
прочитать карту другого аккаунта. Если `WEB_APP_URL` не задан, сам сервер Mini App всё равно
запускается, но кнопка в Telegram не добавляется.

Если Telegram Web (или конкретный клиент) не передал `initData`, Mini App покажет одноразовый
4-значный код регистрации. Скопируй его и отправь боту командой `/link КОД`. После подтверждения ботом
карта загрузится автоматически через временную защищённую сессию; Telegram ID вручную вводить
не нужно.

### Деплой на Railway

В архиве есть `railway.json`, поэтому проект можно загрузить в GitHub и развернуть
на Railway без отдельного Dockerfile. Репозиторий должен содержать
`package.json`, `package-lock.json`, `railway.json`, папку `src/` и `README.md`
прямо в корне, а не внутри дополнительной папки.

1. Создай GitHub repository и загрузи в него содержимое архива.
2. В Railway выбери **New Project → Deploy from GitHub Repo**.
3. В Variables добавь обязательную переменную `BOT_TOKEN`.
4. После первого деплоя скопируй публичный домен Railway и добавь:

   ```text
   WEB_APP_URL=https://ТВОЙ-ДОМЕН.up.railway.app/mini-app
   ```

5. Добавь Railway Volume с mount path `/data` и установи `DATA_DIR=/data`.
   Это сохраняет pairing и настройки после перезапуска контейнера.
6. Сделай redeploy, затем отправь боту `/start`. В клавиатуре появится кнопка
   **Открыть live-карту**.

Railway сам передаёт приложению `PORT`, поэтому `WEB_APP_PORT` настраивать не нужно. Если
`WEB_APP_PORT` случайно остался среди Variables, приложение всё равно предпочитает Railway `PORT`.
Проверка работоспособности доступна по `https://ТВОЙ-ДОМЕН.up.railway.app/health`.
`railway.json` оставляет установку зависимостей стандартному Nixpacks, запускает
`npm start` и перезапускает процесс при падении. Это важно: повторный `npm ci`
в отдельной build-фазе Railway может закончиться ошибкой `EBUSY` на `node_modules/.cache`.

Для локальной проверки без Rust+ можно временно поставить `SIMULATION_MODE=true`.
В боевом режиме оставь `SIMULATION_MODE=false`.

После запуска отправь боту `/start`, затем `/help`.

## Запуск на своём компьютере

### Windows

1. Установи Python 3.10+ с [python.org](https://www.python.org/downloads/), если его ещё нет.
2. Распакуй ZIP в отдельную папку.
3. Дважды кликни `start-bot.bat`.
4. При первом запуске откроется `.env` — впиши туда `BOT_TOKEN`.
5. Запусти `start-bot.bat` ещё раз.

Скрипт сам установит зависимости при первом запуске. Для остановки нажми `Ctrl+C` в окне бота.

Если Python не найден, установи его с [python.org](https://www.python.org/downloads/) и включи опцию **Add Python to PATH**.

Запускатель повторяет схему старого Python-бота: `start-bot.bat` вызывает `python main.py`. Сам `main.py` не меняет функции бота — он только запускает Node-приложение. Если Node.js не установлен, `main.py` автоматически скачает portable-версию Node.js в локальную папку `.runtime` и использует её только для этого проекта.

Если Windows блокирует PowerShell, можно использовать `start-bot.bat`. Для ручного запуска из PowerShell:

```powershell
cd C:\путь\к\rust-telegram-monitor
.\start-bot.ps1
```

### Linux/macOS

```bash
cd rust-telegram-monitor
chmod +x start-bot.sh
./start-bot.sh
```

## Безопасность

Credential Info — это долгоживущие FCM credentials, поэтому отправлять его нужно только своему боту в личный чат, а не в общий чат с друзьями. Сообщение пользователя удаляется после успешного разбора. В `data/state.json` аккаунт хранится в зашифрованном виде; ключ выводится из `BOT_TOKEN`. Не меняй токен бота без резервной копии и не коммить папку `data`.

## Ограничения Rust+

- Универсального события «начался рейд» нет. Надёжный сигнал рейда — Smart Alarm, подключённый к базе.
- Лут контейнера приходит через Storage Monitor, если он установлен на нужном контейнере.
- Rust+ отправляет сообщения в team chat, но не может писать в локальный proximity-chat от имени Steam-аккаунта.
- Rust+ не публикует универсальный API с точным respawn каждого ящика на каждом сервере и не передаёт список Oxide/Carbon plugins. Бот фиксирует `/loot водоочистная`, отслеживает доступные dynamic markers и после повторного появления уточняет средний таймер по фактическим замерам. Для точного времени конкретного сервера нужен plugin/API самого сервера — DeepSeek не может получить эти данные только по названию сервера.
- `RUST_LOOT_MULTIPLIER` и `RUST_RESPAWN_MULTIPLIER` разделены: на текущем сервере в примере стоит `2`; если x2 меняет только количество предметов, оставь respawn multiplier равным `1`.
- Если `MAP_POLL_INTERVAL_MS` поставлен меньше 250, бот использует 250 мс, чтобы не забить Rust+ запросами. Если ответ Rust+ сам занимает 8–10 секунд, уменьшение интервала не ускорит его — в таком случае Mini App получает последнее состояние сразу после ответа, а broadcast-события обрабатываются без ожидания следующего poll.

```text

  credentials.js      разбор Credential Info и pairing notification
  fcm-pairing.js      FCM listener для каждого пользователя

  index.js            маршрутизация событий и уведомлений
  rt-catalog.js       каталог РТ
test/
  smoke.test.js       тесты чистых функций без внешних сервисов
```
